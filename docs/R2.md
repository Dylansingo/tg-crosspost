# R2 staging

Feed and story JPEGs are uploaded only when all five keys are set and the process is not in demo mode:

- `R2_ACCOUNT_ID`
- `R2_ACCESS_KEY_ID`
- `R2_SECRET_ACCESS_KEY`
- `R2_BUCKET`
- `R2_PUBLIC_BASE_URL`

If any key is missing, the bot writes `./out/media/{name}-feed.jpg` and `{name}-story.jpg` and returns `file://` URLs. Demo mode always does that, even when the keys are present. The startup table lists R2 as enabled or disabled, and the following line says `Stager: local files (./out/media)` or `Stager: R2 (https://…)`.

Objects are `media/{name}-feed.jpg` and `media/{name}-story.jpg`. Both are uploaded with `Content-Type: image/jpeg`. The public URL is `R2_PUBLIC_BASE_URL` plus the object key. TikTok photo posts use the story URL (`staged.tiktok` is the same string as `staged.story`).

The S3 endpoint is `https://<R2_ACCOUNT_ID>.r2.cloudflarestorage.com` with region `auto`. Put the real keys in `.env` only. `.env.example` documents the names and stays commented.

## Delete staged objects after one day

Staged media is a hand-off for the publishers. It should not accumulate. Add a lifecycle rule that deletes objects under the `media/` prefix one day after they are written. Cloudflare removes an expired object typically within 24 hours of that expiry, so a one-day rule clears yesterday's renders on the following day. Objects outside `media/` are left alone.

### Dashboard

1. In the Cloudflare dashboard, open **R2 object storage** and select the bucket named by `R2_BUCKET`.
2. Open **Settings**.
3. Under **Object lifecycle rules**, choose **Add rule**.
4. Name the rule `delete-staged-media-after-1-day`.
5. Set the prefix to `media/`.
6. Choose **Delete objects** and set the age to **1 day**.
7. Save the rule.

An API token that changes lifecycle rules needs the **Workers R2 Storage Write** permission.

### Wrangler

The same rule from the CLI:

```bash
npx wrangler r2 bucket lifecycle add "$R2_BUCKET" delete-staged-media-after-1-day media/ --expire-days 1
```

To replace the bucket's lifecycle configuration from a file instead:

```bash
npx wrangler r2 bucket lifecycle set "$R2_BUCKET" --file docs/r2-lifecycle.json
```

`docs/r2-lifecycle.json` is the request body of the Cloudflare lifecycle API (`PUT /accounts/{account_id}/r2/buckets/{bucket_name}/lifecycle`). `maxAge` is in seconds. `86400` is one day.

```json
{
  "rules": [
    {
      "id": "delete-staged-media-after-1-day",
      "enabled": true,
      "conditions": { "prefix": "media/" },
      "deleteObjectsTransition": {
        "condition": { "type": "Age", "maxAge": 86400 }
      }
    }
  ]
}
```

### S3 API

The same retention, expressed as an S3 `PutBucketLifecycleConfiguration` body against `https://<R2_ACCOUNT_ID>.r2.cloudflarestorage.com`:

```json
{
  "Rules": [
    {
      "ID": "delete-staged-media-after-1-day",
      "Status": "Enabled",
      "Filter": { "Prefix": "media/" },
      "Expiration": { "Days": 1 }
    }
  ]
}
```

Sending that document replaces the bucket's existing lifecycle configuration. Include any other rules you still need.

## TikTok PULL_FROM_URL

TikTok photo posts have one media source: `PULL_FROM_URL`. The client calls `POST https://open.tiktokapis.com/v2/post/publish/content/init/` with `media_type: "PHOTO"` and:

```json
"source_info": {
  "source": "PULL_FROM_URL",
  "photo_images": ["https://media.example.com/media/{name}-story.jpg"],
  "photo_cover_index": 0
}
```

TikTok's servers download those URLs. The download is refused with `url_ownership_unverified` until the developer has proved they own the URL prefix or the domain. A public object on `r2.dev` (for example `https://pub-<hash>.r2.dev/...`) cannot pass that check: `r2.dev` belongs to Cloudflare, so the client cannot add TikTok's DNS signature to it. `R2_PUBLIC_BASE_URL` has to be a custom domain attached to the bucket.

What the client needs to do:

1. Attach a hostname the client controls, such as `media.example.com`, to the bucket. In the Cloudflare dashboard: the bucket, **Settings**, **Custom domains**. The hostname must serve the object itself. TikTok treats any HTTP redirect (a 3xx response) as an invalid URL, and it does not follow the redirect.
2. Set `R2_PUBLIC_BASE_URL` to `https://media.example.com` (https, no path, no trailing matter that would change the object URL). The story URL the bot returns is `https://media.example.com/media/{name}-story.jpg`.
3. In the [TikTok for Developers](https://developers.tiktok.com/) portal, open the app and add a property in the **URL properties** widget. The account needs manage or write access to the app.
   - **Domain** (preferred). Add the signature TikTok shows as a DNS record on that hostname. Verifying `media.example.com` covers every path on that host and its subdomains. It does not cover the parent zone (`example.com`) or a different host.
   - **URL prefix**, if a whole-domain proof is not wanted. A prefix is `https://` + host + path + `/`, and the host must be a domain, not an IP address. Verifying `https://media.example.com/media/` covers the keys this bot writes. A prefix has to match exactly, including the trailing slash.
4. Keep each URL available with no redirect until TikTok finishes the download. The download task times out one hour after it starts. The one-day lifecycle rule is longer than that window.
5. Use the verified story URL as the `photo_images` entry. Do not substitute an `r2.dev` URL, a signed URL on another host, or a short link.

Until TikTok has audited the app, photo posts are limited to private accounts (`unaudited_client_can_only_post_to_private_accounts`). Domain verification and the audit are separate steps.

Reference: [Content Posting API, photo post](https://developers.tiktok.com/docs/en/content-posting-api-reference-photo-post) and [Media transfer guide](https://developers.tiktok.com/doc/content-posting-api-media-transfer-guide).
